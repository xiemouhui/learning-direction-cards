# 备份与恢复

## 个人 JSON

设置页下载个人资料 JSON，包含已确认画像、问卷、知识事件、快照、路线版本、任务回报、周反馈、顾问对话、来源、模型选择和浏览器问卷草稿。文件包含个人经历，请自行妥善保存。Key、余额、他人资料、公共搜索缓存、调用日志和内部请求记录不导出。

丢失 Cookie 后，原数据库中的身份不会自动找回。可在新的空白浏览器身份打开设置，选择先前导出的 JSON，检查数量、备份日期和知识版本，输入“恢复到空白身份”后确认。已有知识、问卷、路线或记录的身份会拒绝恢复，不覆盖、不自动合并、不要求先删除现有资料。

恢复支持已知的 exportSchemaVersion=1 和本项目随附知识版本 .1/.2/.3/.4 及 2026-10-21.5。界面接收至多 4 MB 文件；服务器完整请求上限 5 MB，条数也有限制，超限时保留原文件并报错。预览只校验，不导入；确认时再次校验文件哈希和当前身份版本。

全部写入在事务中完成，失败回滚。路线、记录标识重新生成，内部关联映射到当前身份；不会恢复原身份 Cookie。旧路线沿用原知识发布和结果，不用新规则重算覆盖。外部 AI 和搜索始终关闭，需本人重新启用；若包含有效浏览器问卷草稿，会替换本浏览器草稿。恢复后的本地用量从新身份开始，不能当作供应商的完整历史账单。

未知版本、重复标识、错误类型、非法链接、断裂关联、多个活动计划与缺少当前路线版本会拒绝恢复。备份来自用户文件，恢复不等同独立验证其中的自评或历史结论。

## 本机数据库一致性备份

`pnpm backup:database` 使用 SQLite online backup API，将当前配置数据库保存到本项目 `.local/backups/`，保留一致快照并兼容 WAL；不直接复制正在变化的 db/WAL/SHM 文件，不覆盖旧备份。该目录被 Git 忽略，但完整数据库含所有本机身份资料，不能上传公开仓库。

完整数据库备份用于管理员停服务后的故障恢复，不作为网页 JSON 导入文件。本轮没有替换正式数据库、清空资料或测试破坏性整库恢复。更新前备份与 seed 只追加新知识版本，不改个人路线。

## 隔离升级与整库恢复演练

`node scripts/run.mjs recovery-drill` 每次在 `.local/recovery-drills/` 新建唯一目录，只创建虚构 0001 旧库，含两个身份、知识事件、旧 .4 路线与回报。升级到 0002 并重复迁移，比较旧表内容摘要；执行 online backup，在虚构源库删除测试身份，再从备份恢复到另一个新文件，核对全表摘要、外键和 integrity_check。全过程不读取或替换正式数据库，不使用 DATABASE_URL，也没有外部调用。

2026-10-21 演练通过，元数据见忽略目录 `.local/recovery-drills/latest.json`。这是虚构历史结构和隔离整库恢复验证，不等同已对实际历史个人库升级或已进行生产灾难恢复。首次演练因脚本重复建迁移表中止，修正为沿用 0001 已建表后通过；没有正式库影响。

## 行动证据备份

新版任务回报可选保存环境、预期、实际、独立范围、局限、分钟数及路线版本/行动关联；旧式纯文字回报仍可恢复。服务器推导可关联知识，恢复时复核原路线版本和行动，不接受任意知识关联；旧 .4 路线按原发布读取。填入知识证据草稿不自动修改等级。

## 知识撤销

画像页“知识事件历史”中，该知识项最新一次确认可预览并撤销。确认后追加撤销事件，恢复此前完整等级、证据、学习状态与冲突标记；首次确认恢复到未评估。旧事件和路线保留，画像版本递增。再次修改可走常规确认流程；不提供任意历史截断或自动路线替换。事件重放函数和当前投影一致性已测试。
