## 请求和失败边界

每次两路并发，共两组；单请求默认八秒截止，整个检索批次默认十八秒截止，顾问沿用四十五秒总处理预算。不自动搜索重试，也不因无结果换服务商或放宽域名。每个平台最多保留两条筛选结果，合计最多八条，按平台查看引用。

报告逐平台记录实际发出次数、公开查询、返回条数、保留数和状态，区分有匹配、无结果、未通过筛选、失败、超时和未发出即取消。一个平台失败不取消其他平台。有资料但未集齐四平台时标部分结果，不伪造覆盖或宣称四平台共识。来源标题/路径筛选不是事实核验，重复表达或转载也不能证明独立共识。

请求前预占四次当天检索额度；不足四次则整批拒绝，不先搜一部分。总结最多预占一次模型额度。结束按实际发出的请求计数；空结果/失败也计入应用请求次数，不等于服务商计费。中断进程无法准确确认实际调用时，沿用保守预占。当前身份默认每日二十次检索，全部用于对照时最多五轮。

批次截止或设置撤销、画像变更、身份删除后，未开始的下一组不再发送；已发出请求不能撤回。输出写回再次复核身份、设置和画像版本，旧上下文结果不能复活已删除资料。刷新历史不会重新搜索，同一幂等请求不会重复执行。

## 总结规则

模型一次接收通过筛选的公开摘要和逐平台状态，在解释中分段说明平台发现、共同点与分歧、下一步与局限。沿用结构和引用白名单校验，且对照总结必须引用本轮至少一条网页依据，否则保留资料并回退本地提示，不追加模型请求。所有平台都无有效资料时直接显示资料不足。关闭模型时仍可查看独立的平台报告与资料列表，但不生成模型总结。

报告、引用和模式记录在原有个人对话中，刷新保留；个人 JSON 导出与空白恢复保留新报告，旧备份没有这些可选字段仍可读取。全部删除按原规则级联清理。Key、供应商原始错误和请求头不进入报告或备份。
